web-video-presentation Architecture · v1.2.0

文章 → 可录屏的视频舞台

这个仓库不是一个应用，而是一个 Agent Skill：一套协议 + 一份章节写作方法论 + 一个 Vite/React 骨架 + 23 套主题。 Agent 按协议把文章加工成点击驱动的 16:9 网页，再录屏或渲染成片。 trae-harness-video/ 是这套流程跑出来的真实案例（4 章 / 22 步）。

01

仓库是四个面，不是一个应用

协议告诉 Agent 怎么推进，方法论告诉它每章怎么写，骨架提供运行时，主题决定视觉签名。四层解耦，所以换主题不用改章节、换题材不用改骨架。

协议层

SKILL.md

5 个阶段 + 3 个硬停点 + 自检协议。规定 Agent 不许从原文一路闷头做到成品：每一步都要停下来对齐。

references/

templates/

Vite + React + TS。4 个 hook 管游标、缩放、音频、模式；5 个组件管舞台、进度条、揭示动画、自动播放闸门。

4 hooks · 5 组件零状态库

主题层

themes/

每套一个 tokens.css + theme.json：调色板、字体、性格旋钮（圆角/发丝线/hero 数字）、装饰层。不是换色版。

23 套主题改 1 个文件

关键设计：主题只暴露 12 个必填 token（4 表面 / 4 文字 / 1 线 / 3 accent）+ 4 个字体家族，章节被禁止硬编码颜色和字体名 —— 这是"换主题不破"的唯一机制。

02

运行时：一个游标驱动一切

没有路由、没有动画时间线、没有全局状态库。整片进度就是 cursor = { chapter, step }，章节是 step 的纯函数。

渲染链路 / src

registry/chapters.ts
章节顺序数组；每项 = id · title · narrations[] · Component
hooks/useStepper.ts
cursor 状态机：next / prev / jump，localStorage 持久化 + sanitize 越界钳制，键盘 ← → Space 1-9
components/Stage.tsx
1920×1080 原始坐标 → transform: scale() 适配视口；点击空白推进，data-no-advance 挡住交互子元素
<ChapterComponent step={step} />
每步一套独立布局；同一章只做 if (step === N) 分支切换，无定时器
ProgressBar / AutoToggle / AutoStartGate
默认全透明，鼠标到边缘才出现 —— 录屏画面里没有 chrome

单一真相源 / narrations.ts

同一个数组喂三处，无法漂移
  • 01step 总数 = narrations.length（没有 totalSteps 字段）
  • 02口播文本 → extract-narrations → TTS 每步一个文件
  • 03音频路径约定 /audio/<id>/<step+1>.mp3
  • 04空串 "" = 无声过场，Auto 按字数估时
由此得到的三角约束
  • ·chapters.ts 里的 if (step === N) 最大 N + 1 = 数组长度 = 音频文件数
  • ·动画时长 ≤ 该步口播时长，框架不提供"等动画"兜底
03

三种播放模式，只有一个推进者

按 M 循环切换，URL 同步（?audio=1 / ?auto=1），刷新不丢状态。Auto 模式靠音频结束推进 —— 录屏天然音画同步，不需要后期对轨。

Mode 01
manual

静音，点击 / 方向键推进。用来做视觉验收和手动录屏。

推进者：人
Mode 02
audio

每步播放口播音频，但停下来等你点。用来边听边调节奏。

推进者：人 · 声音：步进播放
Mode 03
auto 一镜到底

音频播完 +200ms 自动 next。浏览器禁止无手势自动播放，所以加载时出现一次 AutoStartGate，按 Space 解锁。

推进者：audio.ended · 缺失时 chars × 250ms
04

生产流水线：三个硬停点卡住 Agent

这些 checkpoint 是 Skill 契约的一部分。主题影响动效气质、outline 决定节奏、音频决定成片路径 —— 任何一处猜错，后面全是返工。

Phase 1
内容编写 原文 → 平台化口播稿 + 开发计划（章节 · 节拍 · 信息池 · 素材清单），一次产出两份 script.mdoutline.md
CK · Plan
五件事一次对齐 稿子 / outline / 主题 / 素材 / 开发模式（A 逐章 · B 顺序 · C 并行） 必须停
Phase 2
网页开发 scaffold.sh 建项目 → 第 1 章主线程做完整样板 → 验收 → 第 2~N 章按选定模式铺开 scaffold.shCHAPTER-CRAFT
CK · Ch.1
第 1 章必须人类验收 它是方法论的第一次落地，暴露 token 不够用 / 指引有盲区，早改成本最低 必须停
CK · Audio
是否合成音频 合成 → 自动录屏一镜到底；不合成 → 手动录屏 + 后期配音 必须停
Phase 3
音频合成（可选） 扫 narrations.ts 出 segments.json → 串行 TTS，增量跳过已存在文件 extract-narrationssynthesize-audio.sh
Phase 4·5
成片 录屏（?auto=1 一镜到底，裁头尾即成片）或 HyperFrames 逐帧渲染成 MP4 output.mp4
EXIT A · 录屏浏览器 16:9 全屏 → ?auto=1 → Space → 自动播完 → 裁头尾。声音由页面自己播，不用对轨。
EXIT B · 渲染presentation 的每个 step 转成 .clip 页 → HyperFrames CLI + FFmpeg → 逐帧 30fps MP4。确定性强，可批量。
